WiFiCall - مکمل آڈیو/ویڈیو کال پروجیکٹ
=====================================

اہم بات:
یہ نیا مکمل ابتدائی ورژن ہے۔ دونوں فون الگ الگ موبائل ڈیٹا پر کال کر سکتے ہیں، لیکن اس کے لیے ایپ کو انٹرنیٹ پر HTTPS سرور پر deploy کرنا ضروری ہے۔ صرف اپنے لیپ ٹاپ پر START.bat چلانے سے دور موجود موبائل کال نہیں کر سکیں گے۔

فولڈر میں کیا ہے؟
- server.js: اکاؤنٹ، User ID اور کال سگنلنگ سرور
- public: موبائل ایپ کا انٹرفیس اور WebRTC آڈیو/ویڈیو کال
- render.yaml: Render پر deploy کرنے کی بنیادی ترتیب
- START.bat: لیپ ٹاپ پر مقامی ٹیسٹ

لیپ ٹاپ پر مقامی ٹیسٹ:
1) Node.js 18 یا اس سے نیا ورژن انسٹال کریں: https://nodejs.org/
2) START.bat پر ڈبل کلک کریں۔ پہلی بار npm install انٹرنیٹ سے پیکجز لے گا۔
3) براؤزر میں http://localhost:3000 کھولیں۔
4) مقامی ٹیسٹ میں اسی لیپ ٹاپ کے براؤزر پر اکاؤنٹ بنایا جا سکتا ہے۔ فون پر مائیک/کیمرہ کے لیے HTTPS درکار ہے، اس لیے عوامی HTTPS deploy استعمال کریں۔

انٹرنیٹ پر deploy:
1) GitHub پر نیا repository بنائیں اور اس فولڈر کی تمام فائلیں upload کریں۔
2) Render.com پر اکاؤنٹ بنائیں، New > Blueprint منتخب کرکے GitHub repository connect کریں۔
3) render.yaml کی مدد سے سروس بنے گی۔ deploy مکمل ہونے پر Render ایک https:// والا لنک دے گا۔
4) دونوں موبائلوں میں وہی HTTPS لنک کھولیں، الگ الگ اکاؤنٹ بنائیں، اپنی User ID ایک دوسرے کو دیں اور کال کریں۔

اہم حدود:
- مفت ہوسٹنگ پر سروس کچھ دیر استعمال نہ ہونے پر سو سکتی ہے، پہلی کال/کھولنے میں تاخیر ہو سکتی ہے۔
- موجودہ ورژن STUN استعمال کرتا ہے۔ کچھ موبائل نیٹ ورکس یا سخت NAT پر کال connect نہیں ہو سکتی؛ ایسی صورت میں TURN relay سروس لگانی ہوگی، جو اکثر paid ہوتی ہے۔
- یہ ابھی ابتدائی MVP ہے، مکمل محفوظ تجارتی ایپ نہیں۔ حقیقی استعمال سے پہلے مضبوط سکیورٹی، abuse controls، privacy policy اور TURN ضروریات پوری کریں۔
- پاس ورڈ سرور پر scrypt hash کی صورت میں محفوظ ہوتا ہے؛ اسے کسی حقیقی حساس اکاؤنٹ کا پاس ورڈ نہ بنائیں۔
- Render کے مفت پلان پر فائل سسٹم مستقل نہیں ہوتا؛ سروس دوبارہ بننے یا restart ہونے پر بنائے گئے اکاؤنٹس ضائع ہو سکتے ہیں۔ مستقل اکاؤنٹس کے لیے بعد میں database (مثلاً PostgreSQL) جوڑنا ہوگا۔
